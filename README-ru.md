# Foxhole: голос Vivox вместе с VPN

Если с VPN игра работает, а голос не подключается, этот фикс позволяет пустить два подтверждённых адреса Vivox напрямую через обычный интернет. Остальной трафик продолжает обрабатывать ваш VPN.

Схема проверена 20 октября 2026 года на Windows 11 с Happ 4.5.3 (624), Happ TUN и JSON-подпиской: после добавления двух маршрутов пользователь подтвердил, что голос заработал. Для других VPN совместимость не подтверждена.

У пакета проверены синтаксис Windows PowerShell 5.1, выбор физического шлюза, восстановление маршрутов и сохранение чужих правил на подставной таблице маршрутов. Windows Task Scheduler принял XML задачи без её регистрации. Установка всего пакета и автозапуск после реальной перезагрузки ещё не проверялись.

Перед установкой убедитесь, что без VPN голос работает. Если прямое подключение Vivox блокирует сам провайдер, эта схема не решит такую проблему.

## Как поставить

1. Распакуйте ZIP целиком в отдельную папку. Не запускайте файлы прямо из архива.
2. Подключите обычный интернет через Ethernet или Wi-Fi и включите Happ.
3. Запустите **Install.cmd**. Разрешите повышение прав в запросе Windows.
4. Закройте и снова запустите Foxhole либо нажмите переподключение голоса в настройках звука.
5. Проверьте, что игровые сервисы работают, вы слышите других игроков и они слышат вас.

Программа сама выбирает физический Ethernet/Wi-Fi и его шлюз. Вводить IP роутера, VPN-ключ или токен не нужно. При нескольких физических подключениях выбирается обычный маршрут с наименьшей суммарной метрикой.

Если повышенная установка завершилась ошибкой, окно запуска покажет ошибку установки. Чтобы увидеть подробное сообщение, откройте PowerShell от администратора в распакованной папке и выполните:

```powershell
.\Foxhole-Vivox-Fix.ps1 -Action Install
```

Если Windows или защитное ПО блокирует запуск, не отключайте защиту. Используйте ручную настройку только после проверки содержимого скрипта человеком, которому доверяете.

## Что именно меняется

| Назначение IPv4 | Путь |
|---|---|
| 85.236.98.180/32 | Direct: обычный шлюз Ethernet/Wi-Fi |
| 85.236.98.181/32 | Direct: обычный шлюз Ethernet/Wi-Fi |
| Все остальные адреса | Существующие маршруты, включая VPN |

Маршруты действуют для TCP и UDP к этим двум IP. Это два подтверждённых адреса сервисов Vivox, а не полный список всех возможных SIP/RTP-серверов. В конкретной игровой сессии могут понадобиться другие адреса; их нужно подтвердить по трафику, а не добавлять наугад.

Фикс не меняет DNS, firewall, антивирус, прокси, настройки игры и VPN-сервера. Он не скачивает код, не отправляет логи, не читает VPN-ключи и не использует подписку автора. IPv6 он не меняет. Прямые соединения к указанным адресам будут видеть обычный внешний IP пользователя — это и требуется для обхода VPN.

Файлы устанавливаются в **Program Files\FoxholeVivoxFix**. Обычные пользователи получают только чтение. Задача **FoxholeVivoxFix** запускает локальный скрипт от SYSTEM при старте Windows, входе пользователя и подключении сети. Она восстанавливает два маршрута в ActiveStore, а не записывает постоянный шлюз навсегда. При смене Ethernet/Wi-Fi шлюз определяется заново. Если сеть ещё не готова, задача делает до трёх повторных попыток с интервалом в минуту. Постоянного фонового процесса нет.

Маршруты, уже существовавшие до установки, фикс не удаляет и не присваивает себе. Конфликтующий маршрут с другим интерфейсом или шлюзом останавливает применение.

## Проверка и восстановление

- **Check.cmd** показывает, какой интерфейс Windows выбирает для двух IP, и наличие задачи автовосстановления. Изменений не делает.
- **Refresh.cmd** заново определяет обычное подключение и восстанавливает маршруты. Используйте после смены сети, если автоматическое восстановление ещё не произошло.
- Перезапуски Happ и Steam сами по себе не должны удалять эти маршруты, но это зависит от поведения VPN. После них повторите проверку голоса; отдельно это ещё не проверялось.
- Последний результат фонового восстановления хранится локально в **Program Files\FoxholeVivoxFix\last-result.json**.

## Как удалить

Запустите **Remove.cmd**, подтвердите запрос Windows. Он удалит задачу, свои установленные файлы и только те маршруты, которые создавал сам. Перезапустите голос или игру.

## Если не помогло

1. Оставьте VPN включённым и запустите Check.cmd. Для обоих адресов должен отображаться физический Ethernet/Wi-Fi, а не TUN.
2. Полностью закройте Foxhole и запустите заново: старые соединения могут оставаться привязанными к VPN.
3. Если выбран правильный интерфейс, но голос не работает, дальнейшая диагностика должна определить фактические SIP/RTP-адреса. Подойдут локальный pktmon или Wireshark и сопоставление UDP-портов процесса War-Win64-Shipping.exe с переподключением голоса.
4. VPN с kill switch может запрещать обход через Ethernet/Wi-Fi. В таком случае нужны штатные исключения этого клиента или отдельная конфигурация. Этот скрипт защитные настройки VPN не обходит.

Не направляйте весь UDP напрямую: Foxhole использует UDP и для самой игры. Не исключайте весь процесс игры, если её серверы должны работать через VPN.

## Почему не просто правило в Happ

В Happ готовая JSON-подписка может блокировать пользовательскую маршрутизацию. В проверенной версии приложение прямо показало это ограничение. Поэтому используется таблица маршрутизации Windows.

Для обычного редактируемого подключения в Happ альтернативная схема:

```text
DirectSites: domain:vivox.com
DirectIp:    85.236.98.180/32, 85.236.98.181/32
GlobalProxy: true
RouteOrder:  block-direct-proxy
```

Существующие локальные исключения нужно сохранить. Доменное правило работает, когда ядро видит имя; оно само по себе не гарантирует обработку SIP/RTP по IP. После изменения профиля нужно переподключить VPN. Такая конфигурация отдельно в данной сессии не проверялась.

## Если Vivox сменит IP

Адреса в версии 1.0.0 закреплены по фактической диагностике. Автоматического обновления списка нет. При изменении инфраструктуры нужно заново подтвердить назначения по логам, DNS и трафику, удалить старую версию и поставить обновлённый пакет. Не добавляйте целые подсети по одному соседнему адресу.

Подтверждение текущих адресов: в игре найдены cfmtxp.vivox.com и cfmtxp.www.vivox.com; DNS второго имени вернул 85.236.98.180; соединение самого процесса игры с 85.236.98.181:443 после изменения шло с физического интерфейса, а прямой сервер предоставил сертификат *.vivox.com. Работу голоса подтвердил пользователь.
