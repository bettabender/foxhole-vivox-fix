Версия 1.0.1 · Windows · 22 октября 2026

Foxhole: игра через VPN,
голос Vivox напрямую

Если без VPN голос работает, а при включённом Happ пропадает, попробуйте три точечных исключения Vivox. Игровой трафик продолжит обрабатывать VPN.

Схема сработала с Happ 4.5.3 (624), Happ TUN и JSON-подпиской на Windows 11.

Работу голоса подтвердил пользователь после изменения маршрутов. Для других VPN и всех голосовых серверов результат не гарантирован.

Обновление 1.0.1

Добавлен новый подтверждённый адрес 85.236.105.136/32. После его добавления и полного перезапуска Foxhole пользователь подтвердил работу голоса с Happ. Для обновления запустите Install.cmd из нового архива поверх предыдущей версии. Автоматического обновления списка IP по DNS по-прежнему нет.

Установка в один клик

  1. Распакуйте ZIP целиком в отдельную папку.
  2. Подключитесь к обычному интернету и включите Happ.
  3. Запустите Install.cmd и подтвердите запрос Windows.
  4. Перезапустите Foxhole либо переподключите голос в настройках звука.
  5. Проверьте: работают игровые сервисы, вы слышите игроков и они слышат вас.

Скрипт сам найдёт Ethernet или Wi-Fi и адрес обычного шлюза. VPN-ключи и адрес роутера вводить не нужно.

Точные исключения

85.236.98.180/32, 85.236.98.181/32 и 85.236.105.136/32 идут напрямую через физический шлюз. Для остальных адресов сохраняются существующие маршруты. Исключения действуют для TCP и UDP к этим трём IP.

Это подтверждённые адреса сервисов Vivox, а не полный список всех возможных SIP/RTP-серверов. Фикс не исключает весь процесс Foxhole и не отправляет весь UDP напрямую.

После перезагрузки

Установщик создаёт задачу FoxholeVivoxFix. Она запускает локальный скрипт от SYSTEM при старте Windows, входе пользователя и подключении сети, заново определяя физический шлюз. Файлы находятся в Program Files\FoxholeVivoxFix, обычным пользователям доступно только чтение. Постоянного фонового процесса нет.

Чужие маршруты сохраняются. При конфликтующем маршруте применение останавливается. DNS, firewall, антивирус, настройки VPN и игры не меняются. В пакете нет VPN-ключей, пользовательских логов и личных настроек автора.

Если не заработало

  1. Запустите Check.cmd: для трёх IP должен отображаться Ethernet/Wi-Fi, а не TUN.
  2. Полностью закройте игру и запустите снова: старые соединения могли остаться на VPN.
  3. После смены сети используйте Refresh.cmd.
  4. Если путь верный, а голоса нет, нужно определить фактические SIP/RTP-адреса в этой сессии. Не добавляйте произвольные подсети и весь UDP.

VPN с kill switch может запрещать прямые соединения. Если Vivox блокируется и без VPN, этот способ также не подходит. Изменение IP Vivox потребует нового подтверждённого списка — автоматического обновления списка в версии 1.0.1 нет.

Что проверено

Рабочая схема проверена в игре у одного пользователя. У скрипта проверены синтаксис, определение шлюза, повторное применение, смена шлюза, восстановление после потери маршрутов и защита чужих правил на подставной таблице маршрутов. Планировщик Windows принял XML задачи без регистрации.

Установка всего пакета и реальный автозапуск после перезагрузки ещё не проверялись. Это открытые скрипты Windows, а не подписанный EXE.
