# Foxhole Vivox Fix

Неофициальный фикс для Windows: игровые подключения остаются через VPN, а два подтверждённых адреса Vivox идут напрямую через Ethernet или Wi-Fi.

Подходит для случая, когда **без VPN голос работает, а с VPN игра работает, но голос не подключается**.

## Скачать и установить

**[Скачать ZIP v1.0.0](https://github.com/bettabender/foxhole-vivox-fix/releases/download/v1.0.0/Foxhole-Vivox-Fix-v1.0.0.zip)** · [Страница выпуска](https://github.com/bettabender/foxhole-vivox-fix/releases/tag/v1.0.0)

1. Распакуйте архив целиком.
2. Включите обычное подключение к интернету и Happ.
3. Запустите **Install.cmd**, подтвердите запрос Windows.
4. Перезапустите Foxhole либо переподключите голос в настройках звука.
5. Проверьте игровые сервисы и звук в обе стороны.

Это набор открытых скриптов PowerShell/CMD, а не подписанный EXE. Требуются права администратора для добавления маршрутов и задачи автозапуска.

## Что делает фикс

| Назначение | Маршрут |
|---|---|
| `85.236.98.180/32` | Direct через физический Ethernet/Wi-Fi |
| `85.236.98.181/32` | Direct через физический Ethernet/Wi-Fi |
| Другие адреса | Существующие маршруты, включая VPN |

Шлюз и интерфейс определяются автоматически. Фикс не изменяет DNS, firewall, антивирус, настройки игры и VPN. Не исключает весь процесс Foxhole и весь UDP. Не читает VPN-ключи и не отправляет журналы.

Установка создаёт задачу `FoxholeVivoxFix`, которая запускает локальный скрипт от SYSTEM при старте Windows, входе пользователя и подключении сети. Файлы хранятся в `Program Files\FoxholeVivoxFix`; обычным пользователям разрешено только чтение. Задача восстанавливает два временных маршрута для актуального физического шлюза. Постоянного фонового процесса нет.

## Проверка, восстановление, удаление

- **Check.cmd** — показать путь к двум IP, без изменений.
- **Refresh.cmd** — восстановить маршруты после смены сети.
- **Remove.cmd** — удалить задачу, файлы фикса и только созданные им маршруты.
- **[Полная инструкция на русском](README-ru.md)** — ошибки, ограничения, ручная диагностика и альтернативные правила Happ.

## Что проверено

Схема с двумя маршрутами сработала 20 октября 2026 года у одного пользователя на **Windows 11, Happ 4.5.3 (624), Happ TUN, JSON-подписка**: сам процесс игры подключился к подтверждённому адресу Vivox через физический интерфейс, пользователь подтвердил работу голоса при включённом VPN.

У установщика проверены синтаксис Windows PowerShell 5.1, автоматический выбор шлюза и сценарии маршрутизации на подставной таблице маршрутов: повторное применение, смена шлюза, восстановление после потери маршрутов, сохранение чужих правил и остановка при конфликте. Windows Task Scheduler принял XML задачи без её регистрации.

**Полная установка пакета, запуск после реальной перезагрузки, другие VPN и другие компьютеры ещё не проверены.** Первая публичная версия опубликована как предварительная.

## Ограничения

- Два адреса не являются полным списком SIP/RTP-серверов Vivox. Если в вашей сессии используются другие серверы, потребуется дополнительная диагностика.
- Список IP не обновляется автоматически. При смене адресов Vivox нужна новая подтверждённая конфигурация.
- VPN с kill switch может блокировать обход через физический интерфейс.
- Фикс не поможет, если голос не работает и без VPN.
- IPv6 не меняется.
- Готовая JSON-подписка Happ может игнорировать пользовательские правила; этот способ работает на уровне маршрутизации Windows.

## Проверка исходников

На Windows из корня репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Foxhole-Fix.ps1
```

Тесты не регистрируют задачи и не изменяют реальные сетевые маршруты. Сетевые команды заменены подставными функциями; формат задачи проверяет локальный планировщик Windows без регистрации.
